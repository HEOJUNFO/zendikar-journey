# 지도 v2 (world-v2/)

레벨 디자인을 처음부터 다시 하는 지도다 (사용자 결정 2026-10-03). 게임은 아직 v1(`world/`)을 쓰고, v2 는 웹의 `#/v2` 페이지에서만 본다. v1 의 데이터·페이지·저장은 건드리지 않는다.

## 순서

1. **전체 지도**: 대륙·섬·바다의 자리와 크기 (2026-10-03).
2. **대륙별 지역·장소**: 한 대륙씩 지역과 장소만 짓고, 대륙마다 사용자에게 보여 확인받는다. 인물·생물·주문·아이템·사건은 넣지 않는다.
3. **카드**: 사용자가 요청한 카드만 한 장씩, v2 의 지역·장소에서 자리를 찾아 넣는다.

## 원칙

- MTG 젠디카르 설정을 어기지 않는 선에서 자유롭게 짓는다 (사용자 말).
- 공식 전체 지도는 없다. 저장소의 `map/`(로컬에만 둔다, `.gitignore`)에 있는 팬 지도 "Planar Map of Zendikar"를 대륙 모양과 대륙 안 배치의 참고로 쓴다. 팬 지도가 설정과 부딪히면 설정을 따른다.
- 설정끼리도 어긋나는 곳이 있다. 그럴 때는 다음 순서로 따른다.
  1. A Planeswalker's Guide to Zendikar, Plane Shift: Zendikar, 매직 스토리, The Journal of Javad Nasrin
  2. The Art of Magic: The Gathering – Zendikar (MTG 위키 인용)
  3. 소설 (MTG 위키 요약)
  4. MTG 위키 편집자의 글, 팬 글: 근거로 쓰지 않는다.
- 시기는 ZEN 블록(젠디카르·월드웨이크·엘드라지 부활, 2009~10)만 담는다 ([결정] 2026-10-03). 바다 관문은 온전하고 할리마르는 차 있으며 인어 은신처가 서 있다. BFZ·ZNR 이후에만 있는 곳(코랄헬름, 하늘 바위, 티칼 정박지, 고스트워치, 스카이클레이브 등)은 넣지 않는다. 나중 시기의 글(Art of Zendikar 등)도 ZEN 시기의 모습을 말하는 대목은 쓴다.
- 해석에는 v1 처럼 출처를 붙인다. [배경]은 설정, [가공]은 설정에 없어 지은 것, [결정]은 사용자와 정한 것이다.
- 같은 곳은 v1 과 같은 id 를 쓴다. 나중에 카드의 `entities` 가 그대로 맞는다.

## 단위

- 지도는 120×90칸이다. 한 칸은 걸어서 1시간이고, v1 과 같은 `TILE` 이다.
  - 설정의 여행 시간보다 훨씬 줄인 게임 단위다 ([가공]). 아게딤을 건너는 데 설정은 보름이 걸리지만 이 지도에서는 반나절이다.
  - 그래서 설정의 거리는 땅과 땅 사이의 비율로만 맞춘다.
- 대륙 → 지역 → 장소 ([결정] 2026-10-03).
  - 지역: 땅이다(유대·마나, 지형대로 기본 땅 종류). 10칸 이상이고, 대륙을 모두 나눠 가진다.
  - 장소: 도시·신전·폐허·야영지 같은 곳이다. 땅이 아니고(`sim: { not_land: true }`), frontmatter 에 `place: true` 를 단다. 1~4칸이고 지역 안에 둔다. 1칸은 신전·폐허·야영지, 2~4칸은 마을·도시다. 그곳을 가리키는 대지 카드가 오면 그때 땅으로 바꾼다.
- 대륙·섬·바다는 첫 겹 `map/world.txt` 에, 대륙의 지역은 `map/<대륙>.txt` 에, 장소는 `map/<대륙>-places.txt` 에 칠한다.
- 크기: 대륙은 구역을 포함해 100칸 이상, 섬과 지역은 10칸 이상, 장소는 1~4칸이다 (`sim/footprint.ts` 의 `sizeProblems`, `npm run world2:check`).

## 파일

- `entities/locations/*.md`: v1 location 과 같은 frontmatter 다.
  - `map` 에 `x`, `y`, `tiles`, `pos`, `order` 를 적지 않는다. 칸은 격자가 정하고, 자리는 칸들의 가운데다. 걸어 다니는 곳(`sim.wanders`)만 칠하지 않고 `x`, `y` 를 적는다.
  - `status: canon` 인 것만 지도에 오른다.
  - `sources` 는 카드가 들어오기 전까지 비어 있다.
  - `design` 은 레벨 디자인이다: `role`(역할), `danger`(위험도 1~5), `note`(한 줄 메모).
- `map/layers.yaml`: 격자의 겹과 범례(글자 → 지역 id).
  - 첫 겹은 지도 전체다. `.` 은 먼 바다로, 누구의 것도 아니다.
  - 다음 겹은 `origin: [열, 행]`부터 칠한다. 0부터 세며, world.txt 에서 그 글자의 자리다. 다음 겹의 `.` 은 그대로 둔다.
  - 구역은 바깥 땅을 칠한 겹보다 뒤 겹에, 바깥 땅의 칸 위에 칠한다. 구역 안의 구역은 그 구역의 칸 위에 칠한다 (`sim/footprint.ts`).
- `map/world.txt`: 첫 겹.
- `map/reference.yaml`: 참고 지도 겹치기. 팬 지도의 각 땅 조각(윤곽)을 v2 가 그 땅을 놓은 자리에 겹치는 행렬이다.
- `map.svg`: 미리보기 (`npm run world2:map`).
- 검사 메시지의 위치 표기:
  - 격자 파일: 몇째 줄 몇째 글자 (1부터)
  - 칸: `칸 열,행` (0부터)

역할은 다음과 같다.

- 거점: 사람이 모이고 길이 시작되는 곳
- 길목: 땅과 땅을 잇는 좁은 곳
- 변경: 탐험하는 야생
- 위험지: 위험한 땅
- 바닷길: 배로 건너는 물
- 끝땅: 가장 늦게 닿는 곳

## 전체 지도의 배치와 근거 (2026-10-03)

**대륙들이 한가운데 무라사를 둘러싼 고리다 [가공]**
- 시작 거점은 타짐의 바다 관문이다. 길은 셋으로 갈린다.
  - 북동쪽 뭍길: 좁은 바다 건너 굴 드라즈(첫 위험지) → 보더마이어 늪 목 → 발라 게드 → 메사 지대 → 늪 → 아쿰
  - 서쪽: 큰 바다 건너 온두 → 북쪽 베이엔의 줄라포트에서 작은 바다 건너 아쿰
  - 북쪽: 바다 건너 무라사(닫힌 대륙)
- 아쿰은 두 길이 만나는 끝 무렵의 위험지이고, 그 너머 북쪽 끝이 세지리(끝땅)다.

**팬 지도와 다른 점**
- 온두: 북서 → 남서
- 온두의 섬들: 온두 동쪽 → 아게딤·즈와르는 남쪽(설정), 베이엔은 북쪽([결정]: 아쿰으로 가는 짧은 뱃길)
- 아쿰: 북동 → 북쪽, 온두에서 작은 바다 하나 건너
- 발라 게드: 굴 드라즈 동쪽 끝 → 북쪽. 아쿰과는 메사 지대와 늪으로 이음
- 타짐: 남서쪽 구석 → 남쪽 가운데, 78도 회전
- 무라사: 타짐과 굴 드라즈 사이 → 한가운데. 일곱 대륙 가운데 가장 작게 줄였다.

대륙의 모양은 팬 지도에서 땄다. 섬 셋은 팬 지도에서 너무 작아 손으로 다시 그렸다.

**맞추지 못한 설정**
- 소설은 턴팀버에서 우긴의 눈이 "서쪽"이라고 하지만, 이 지도에서는 북쪽이다.
- 소설은 아게딤의 들판을 지나 걸어서 줄라포트(베이엔)에 닿아 베이엔을 아게딤 곁에 두는 셈이지만, 이 지도의 베이엔은 온두 북쪽이다. PWG 는 베이엔의 방위를 말하지 않는다. 아쿰을 온두 북쪽에 둔 이 지도에서 소설의 짧은 뱃길을 살리려는 [결정] 이다.

둥근 세계(지도의 동서 끝을 이어 아쿰을 팬 지도처럼 북동쪽에 두는 안)는 쓰지 않는다. 1순위 설정은 지금 배치로 다 맞고, 엔진의 거리 계산을 바꾸지 않아도 되며, 아쿰에 두 길(뭍길·바닷길)로 닿는 고리가 레벨 디자인으로도 낫다 ([결정] 2026-10-03).
